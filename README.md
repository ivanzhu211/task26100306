# burndown — 冲刺历史燃尽核算库

Go 库，由上层直接调用，故事事实与核算数据全部保存在进程内存。
支持补录、更正、撤销故事事实，并可复现任一历史观察版本的燃尽报告。

## 核心概念

- **冲刺**：上层预先定义编号与开始日期。每个冲刺从 UTC 零点开始，持续
  14 天，包含开始时刻、不包含结束时刻，定义不可修改。
- **事实**：故事在某业务时刻的完整状态（所属冲刺 / 未入冲刺、点数、
  是否完成）。每条事实有稳定标识；同一故事的业务时刻互异，到达顺序任意。
- **观察版本**：每次提交（新增 / 更正 / 撤销）产生一个递增版本。
  报告按（冲刺, 版本）查询，只使用截至该版本已收到的事实及其当时最新
  修订；后来的提交不会改变旧版本报告。

## 使用示例

```go
l := burndown.New()

// 1. 预先定义冲刺（开始时刻必须是 UTC 零点，定义不可修改）
t0 := time.Date(2026, 1, 5, 0, 0, 0, 0, time.UTC)
_ = l.DefineSprint(1, t0)

// 2. 提交事实（每次提交返回新的观察版本）
v1, _ := l.SubmitAdd(burndown.Fact{
    FactID:  "f-001",
    StoryID: "US-12",
    Time:    t0,                       // 业务时刻
    State:   burndown.State{SprintID: 1, Points: 5},
})
// 更正：只替换状态，故事编号与业务时刻不变
v2, _ := l.SubmitCorrect("f-001", burndown.State{SprintID: 1, Points: 8})
// 撤销：该事实不再存在，前一状态延续到下一条有效事实
v3, _ := l.SubmitRevoke("f-001")

// 3. 查询报告：必须同时指定冲刺与观察版本
rep, _ := l.Report(1, v1)   // 复现 v1 时公布的图，不受 v2/v3 影响
fmt.Println(rep.Opening)    // 开场承诺点数
fmt.Println(rep.Days[0])    // 第 1 天：日终剩余点数 + 范围净变化
```

`burndown.NoSprint` 表示故事未入任何冲刺。

## 报告口径

- **开场承诺**：冲刺开始时刻已生效、且属于本冲刺的故事点数之和，
  包含已完成故事。
- **日终剩余**：仍属本冲刺且未完成的故事点数之和。日终取次日 UTC 零点
  之前的状态，恰在次日零点生效的事实归次日。
- **范围净变化**：日终总范围（仍属本冲刺的全部故事点数）减开场承诺。
  完成后移出会减少范围，重新打开会增加剩余，估点调整按当时状态反映；
  故事移到另一冲刺时，两个冲刺各自正确体现变化。

## 测试与性能验证

```sh
go test ./...                    # 全部单元测试 + 随机历史逐版本重放比对
go test -run TestPerfScale -v    # 规模性能验证（固定种子，可重复）
go test -short ./...             # 跳过性能测试的快速回归
```

性能验证规模：5 万故事、500 冲刺、20 万原始事实 + 5 万更正/撤销
（含单一故事集中 2 万条事实），随后连续查询 5000 份覆盖不同观察版本
与冲刺的报告。本机（Apple Silicon）实测：全部提交约 0.3 秒（限 60 秒），
5000 份报告约 0.25 秒（限 3 秒），堆内存约 76 MiB（限 512 MiB）。

## 实现要点

- 每次提交把受影响的状态区间转成**段**（业务时间区间 × 观察版本区间），
  追加到对应冲刺的段日志；更正 / 撤销只关闭旧段、开启新段，历史段不
  改写，因此任一旧版本报告可原样复现。
- 每次提交只影响被改事实及其前驱，O(log n) 定位，段总量与提交量线性。
- 报告按冲刺过滤版本可见的段并扫描 15 个日界线，成本与该冲刺的段数
  成正比，与全局故事数、版本数无关。
- 调用方需串行调用；库不提供并发写入、持久化与中断恢复。
