# burndown — 冲刺历史燃尽核算库

Go 库，由上层直接调用，故事事实与核算数据全部保存在进程内存。
支持补录、更正、撤销故事事实，并能按（冲刺, 观察版本）复现任意
历史时刻公布过的燃尽报告：旧版本报告不受后续提交影响。

## 业务规则要点

- 冲刺由上层预先定义（编号 + UTC 零点开始日期），固定 14 天，
  含开始时刻、不含结束时刻，定义不可修改。
- 上层提交故事在某业务时刻的完整状态（所属冲刺/未入冲刺、点数、
  是否完成）。每次提交（新增/更正/撤销）产生一个递增的观察版本。
- 更正只替换状态，不改变故事编号与业务时刻；撤销相当于事实不再
  存在，前一状态延续到下一条有效事实。
- 报告必须同时指定冲刺与观察版本，只使用截至该版本已收到的事实
  及其当时最新修订。
- 开场承诺 = 冲刺开始时刻已生效且属于本冲刺的故事点数之和
  （含已完成故事）。每天给出日终剩余点数与相对开场承诺的范围
  净变化（日终总范围 − 开场承诺）。恰在日界线零点生效的事实归
  次日；恰在冲刺结束时刻生效的事实不属于本冲刺。

## 调用说明

```go
l := burndown.NewLedger()

// 1. 预先定义冲刺（开始时刻必须是 UTC 零点）。
_ = l.DefineSprint("S1", time.Date(2026, 1, 5, 0, 0, 0, 0, time.UTC))

// 2. 提交事实（任意到达顺序；业务时刻为故事维度互异）。
v1, _ := l.AddFact("f-1", "story-A",
    time.Date(2026, 1, 4, 10, 0, 0, 0, time.UTC),
    burndown.State{Sprint: "S1", Points: 5})

// 3. 更正 / 撤销（针对尚未撤销的事实）。
v2, _ := l.CorrectFact("f-1", burndown.State{Sprint: "S1", Points: 8})
v3, _ := l.RetractFact("f-1")

// 4. 查询报告：必须指定冲刺与观察版本。
rep, _ := l.Report("S1", v1)   // 复现 v1 时公布的图
fmt.Println(rep.OpeningCommitment)
for d, day := range rep.Days {
    fmt.Printf("day %d: remaining=%d netScopeChange=%+d\n",
        d+1, day.Remaining, day.NetScopeChange)
}
_, _ = v2, v3
```

注意事项：

- `State.Sprint` 为空串表示未入冲刺；引用的冲刺必须先定义。
- 同一故事的未撤销事实之间业务时刻必须互异；点数为负会报错。
- `Report` 的版本不得超出 `l.Version()`；版本 0 表示无任何提交。
- 库不是并发安全的，调用方需串行访问；不提供持久化。

## 实现结构

- `types.go` — 对外类型：`State`、`Report`、`DayResult`、`Version` 等。
- `errors.go` — 提交的校验错误集合。
- `story.go` — 单故事事实存储：按业务时刻有序，修订按版本有序。
- `ledger.go` — 账本入口：冲刺定义、新增/更正/撤销、候选集索引。
- `report.go` — 报告核算：候选故事单次扫描推进 15 个检查点。

正确性核心：事实的修订与撤销只追加版本化记录，从不改写历史；
报告按版本过滤重放，因此旧版本报告天然不可变。每个冲刺维护
“曾声明属于本冲刺”的候选故事集合（只增不减），把单次报告的
扫描范围限制在相关故事内。

## 测试与性能验证

```sh
go test ./...            # 全部单元测试 + 随机重放一致性 + 规模性能
go test -short ./...     # 跳过规模性能测试
go test -run TestPerformanceScale -v ./...
```

- `ledger_test.go` — 晚到事实改变开场承诺但旧版本不变、撤销跨
  冲刺移出后两冲刺同时修正、完成/重新打开/估点变化发生在冲刺
  开始、日界线与结束时刻、提交校验等。
- `replay_test.go` — 随机小历史（400 次混合提交）的每个观察
  版本 × 每个冲刺，都与独立的从头重放实现逐日一致。
- `perf_test.go` — 固定随机种子的规模验收：5 万故事、500 冲刺、
  20 万事实 + 5 万更正/撤销（含单故事 2 万条事实），提交 < 60s、
  堆内存 < 512MiB；随后 5000 份覆盖不同版本与冲刺的报告 < 3s。
  本机实测：提交约 0.75s，堆约 59MiB，5000 份报告约 1.8s。
